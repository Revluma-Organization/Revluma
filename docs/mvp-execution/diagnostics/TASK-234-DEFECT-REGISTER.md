## Implementation priority and code-retention decision

The high-impact confirmed **Task 234 code defects** were implemented in the source merged by PR #404: deterministic general-knowledge routing and explicit fast/deep model roles; provider retry/failure semantics and bounded time budget; identifier-safe/high-cardinality-bounded metrics; trace continuity through the retained image route; and atomic first-turn persistence with truthful history. Regression coverage is in `python/tests/test_rev_task234_end_to_end_matrix.py`, the provider gateway/policy and architecture suites, plus `Backend/src/services/__tests__/revSubmission.test.js`, `Backend/src/controller/__tests__/revPersistence.contract.test.js`, and the Node/Python trace and metrics tests. The two additional CORS/sync-status fixes in this active branch are **local and not merged or deployed**. Fresh current Python execution is recorded in the linked completion report. These are local/CI results, not production smoke evidence.

No implementation path was removed: source and test evidence show the legacy Python `/orchestrate` route remains in use for image-capable requests, while ordinary JSON/stream questions use `/rev/investigate` and `/rev/stream`; Node synchronous and SSE handlers have distinct persistence/recovery paths. The in-process metrics limitation remains an explicit P2 operational gap requiring deployment aggregation. The unresolved P1 production gate is not a code fix that can be safely inferred or claimed from local tests.

## Retained-path decision

The new investigation entry points and the legacy `/orchestrate` path overlap in request tracing and chat persistence but have different image and response contracts. This work instruments both paths; it does not delete or redirect the legacy path without proving it unused and establishing behavior parity. The synchronous Node chat handler and streaming handler also maintain separate persistence/error paths, so both receive metrics rather than assuming one is dead.
