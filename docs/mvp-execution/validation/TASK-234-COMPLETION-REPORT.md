## Confirmed defects, root causes, and remediations

These are confirmed source/runtime defects, not a proven explanation for the original production incident. Exact incident attribution remains unknown without its correlation ID or equivalent safe log evidence.

1. **General definitions could be routed into store investigation.** A clear definition such as “What is Shopify?” had no deterministic knowledge path, leaving `requires_store_data` dependent on model classification. A narrow definition route now handles context-free definitions only; explicit store metrics/references remain investigative. Tests assert answer, no domain evidence/tool/specialist dispatch, and no unintended persistence.
2. **Model identifiers were presented as if they were routing selectors.** `UNDERSTANDING_MODEL` claimed a Sonnet model although understanding used the gateway's `fast` role; responder vendor-name constants likewise described roles, not guaranteed actual provider selection. These misleading constants were replaced by explicit `FAST_ROLE` / `DEEP_ROLE` selectors, and actual model resolution is centralized in the gateway.
3. **Provider errors were not consistently normalized, observable, or truthful.** Anthropic errors lacked safe correlated telemetry; some responder paths converted exhausted provider errors into fallback prose; configured fallbacks could be attempted for permanent auth/unknown-model failures; attempt counts reflected candidates rather than actual calls; and timeout budgeting could leave the retry with an unbounded share of remaining time. The gateway now normalizes bounded error categories, retries only retryable failures, reports actual attempts, divides one monotonic budget between at most two attempts, and excludes prompt/key/raw exception text from logs. Typed exhaustion reaches the API/stream boundary as a safe provider failure.
4. **Fallback boundaries were ambiguous.** Cross-provider use is now opt-in via `AI_FALLBACK_PROVIDERS`; absent explicit configuration, only a configured same-provider model fallback may be used. Grounded web-search work is Gemini-only. The implementation does not silently erase grounding requirements or transfer prompts to another provider.
5. **Model role/configuration source of truth.** Current defaults in `model_gateway.py` are Anthropic fast `claude-haiku-4-5-20251001`, deep `claude-sonnet-4-6`, with `ANTHROPIC_FAST_MODEL` / `ANTHROPIC_DEEP_MODEL` overrides; Gemini fast `gemini-2.5-flash-lite` and deep `gemini-2.5-flash`, with corresponding Gemini model settings. These are code defaults, **not evidence of the model/provider actually configured or used in production**.
6. **Metrics could leak identifiers and grow without bound.** Arbitrary labels, including correlation/execution IDs, could create high-cardinality series. Node and Python metric dimensions are now allowlisted, values/retention are bounded, and each process has a 512-series ceiling. Metrics remain process-local (not durable or automatically aggregated across instances); that is a known limitation, not a newly implemented exporter.
7. **Trace continuity broke on retained image/orchestration path.** Node accepted execution/correlation IDs but its `mlService.orchestrate` path failed to pass them consistently, and Python could mint a new correlation ID. IDs now propagate across the retained route, trace context, and response metadata. The legacy `/orchestrate` route remains because it still serves the image-capable chat compatibility path; it was instrumented, not deleted.
8. **The legacy orchestrator hid provider failure semantics and telemetry.** It caught provider errors generically and omitted new trace/request/latency counters. It now preserves safe typed provider metadata and bounded trace/latency/failure counters through the endpoint.
9. **Initial conversation acceptance was not atomic.** Conversation and first user message writes were separate, permitting an empty active thread after interruption/failure. They now share a transaction; history suppresses message-less records and derives displayed counts from persisted messages. Regression tests cover rollback and list/search branches. Historical production orphans were not deleted.
10. **Conversation restoration and follow-up continuity had separate gaps.** Follow-up period resolution read only top-level dates despite the persisted nested `last_investigation.period`; it now accepts both shapes. Node restoration instrumentation sat outside a helper that swallowed database failures; failure counting/correlation now occurs inside the catch while bounded fallback-context behavior is retained.
11. **Stream retry could authorize the wrong conversation identifier.** The reuse path passed an undefined `conversationId` instead of `requestedConversationId`. It now authorizes the supplied conversation through the existing tenant-ownership gate; the recovery path remains idempotent.
12. **Unconfigured Node-to-Python gateway failure split trace identity.** Failure handling minted a new execution ID and an early SSE exit omitted trace/provider-unavailable metadata. The failure now retains request IDs and increments the bounded failure metric; configuration failure remains fail-closed and does not call Python.
13. **Python conversation-contract tests were coupled to live providers.** Tests for routing/contracts could fail during a provider outage unrelated to the contract. Shared deterministic composer doubles isolate those tests; gateway retry/provider policies remain tested separately with fakes. Those doubles do not certify generated prose quality.
14. **Authoritative 48-case list was initially ambiguous.** The task owner confirmed the repository matrix as authoritative; it is now explicitly named and contains exactly 48 unique IDs across the six requested categories.

The evidence for these code-level findings and affected paths is maintained in `diagnostics/TASK-234-DEFECT-REGISTER.md`; this report adds the current revision/test/deployment checkpoint and makes the remaining production gate explicit.

## Routing, orchestration, specialists, and restoration

- The browser talks to the authenticated Node gateway. Ordinary chat/stream requests enter Python through `/rev/investigate` or `/rev/stream`; Node resolves tenant identity, validates ownership, accepts/idempotently persists the user turn, and supplies bounded context. Python's `route_message` applies deterministic guards/intent before domain retrieval. General knowledge/advisory and social/continuity paths can return without store evidence tools. Store-specific questions proceed through allowlisted, read-only evidence retrieval.
- `question_orchestration.py` builds bounded tenant-scoped domain tasks, a de-duplicated tool set, deadlines, and bounded transient retry. Selected specialists calculate only from supplied evidence; reconciliation does not promote unverified hypotheses to facts. The matrix covers revenue, checkout, integration, operations, retention, multi-domain plans, and retry behavior. Permanent specialist failure is asserted not to retry or promote facts.
- The legacy Python `/orchestrate` route remains live in source for image-capable compatibility requests; ordinary JSON/stream investigation uses the newer path. It is not assumed dead or removed until image contract parity is demonstrated.
- Node transcript restoration and Python investigation context/memory are distinct layers. Local tests cover tenant-scoped conversation reads, first-turn transaction/recovery, persisted nested periods, retry reuse, restoration-failure metrics, and trace identity. This proves code/test behavior only; **authenticated production conversation restoration has not been exercised**.
