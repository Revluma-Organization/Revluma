## 3. Runtime truth: does the merchant-facing runtime use an objective-driven LLM tool loop?

**No.** The authoritative ordinary merchant path is evidence-first and deterministic after model understanding:

```text
Dashboard revStream.ts
  → authenticated/rate-limited Node /api/v1/rev/stream
  → revController context/authorization/idempotency
  → mlService.streamInvestigation (internal auth, IDs, deadlines)
  → Python /rev/stream
  → investigation.stream_investigation / run_investigation
      → route_message deterministic guards + LLM understanding (fast role)
      → knowledge source routing (public/web isolation; tenant hybrid memory only on explicit opt-in)
      → understand_question + build_investigation_plan (deterministic domain→tool mapping)
      → store_health / fixed run_tool calls (read-only, sequential DB session)
      → evidence/coverage validation + bounded specialists over shared evidence
      → reconciliation, claims/outcomes/answer guardrails
      → optional LLM response composition; SSE final
  → Node independently validates/persists final; Dashboard parses the envelope
```

The LLM's understanding schema asks for intent, objective, store/web requirements and broad domains. It does not receive executable Shopify tool schemas. Python chooses the tool list from a closed mapping; `run_tool` executes it; the response/evidence validators inspect results. Consequently the system is **not** an objective-driven LLM tool-selection loop, even though it does run real deterministic tool execution within the authoritative source path. The model sees no unrestricted Shopify tool dump, but it also does not receive a dynamically filtered tool set or select tools itself.

A separate `python/src/agents/orchestrator.py::orchestrate` path still exists for legacy/compatibility use (including image orchestration). Both the legacy path and authoritative knowledge route now defer private-memory access until after request understanding and require a tenant-context route before invoking tenant-filtered hybrid memory retrieval. This is not a model tool-use loop, and the public document corpora remain unconfigured.
