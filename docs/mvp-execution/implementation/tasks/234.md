# Task 234 — partial implementation (not production-ready)

- Removed recovery discount creation and SendGrid recovery delivery code. Enqueue and direct processing are inert even if legacy beta switches are enabled; old queue records remain untouched. The scheduler retains the existing internal pending-to-abandoned lifecycle update, but does not claim or send sequence jobs. Existing queue backlog requires an explicitly designed reconciliation/retention policy, not false sent/cancelled states.
- Product description confirm/rollback is disabled regardless of `COMMERCE_ACTIONS_ENABLED`, and the direct product adapter rejects writes without invoking its transport. Historical reconciliation and preview remain available. Capability output reports no execution; historical rollback is not advertised as available. Existing fixed mutation query constant remains unused; this is not a universal Shopify transport firewall. Webhook subscription creation is legitimate infrastructure mutation and remains operational.
- New OAuth requests discard configured scopes outside `read_*`. Existing installations may still retain old grants; reauthorization and active-store verified scopes remain outstanding.
- Production global error handler no longer returns 5xx error messages or stack traces even when legacy `EXPOSE_ERROR_DETAILS` is set. This is not a complete Node/Python log-redaction framework; arbitrary 4xx messages and other logging paths remain under review.

No RLS migration, secret rotation, model-context change or tenant-isolation claim has been made. Task 233 recovery risks, business-state completion and privacy deletion issues remain relevant dependencies. All changes need full regression and production verification before release.
